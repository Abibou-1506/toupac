Gestion des erreurs

Toute erreur renvoie un corps JSON. Deux formes seulement, selon qu'il s'agit d'une erreur générale ou d'une validation de champs.

Erreur générale
{
  "detail": "Cette clé API n'a pas le scope requis pour cet endpoint.",
  "status_code": 403
}
Erreur de validation
{
  "seat_label": ["Ce siège est déjà réservé pour ce voyage."],
  "amount_xof": ["Assurez-vous que cette valeur est supérieure ou égale à 1."],
  "status_code": 400
}

Une erreur de validation est indexée par nom de champ, la valeur étant une liste de messages. Le champ status_code reprend le statut HTTP, pour les clients qui ne le lisent pas facilement.

CodeSignificationQue faire
200Succès —
201Ressource créée Le corps contient la ressource, avec son id.
400Requête invalide Corrigez les champs listés. Ne réessayez pas à l'identique.
401Authentification absente ou invalide Vérifiez l'en-tête X-API-Key et que la clé n'est ni expirée ni révoquée.
403Authentifié mais non autorisé Scope manquant. Demandez son ajout à votre contact TOUPAC.
404Ressource inexistante Vérifiez l'identifiant. Une ressource d'une autre compagnie répond aussi 404 : nous ne révélons pas son existence.
429Quota dépassé Attendez la durée de Retry-After. Voir Quotas.
500Erreur serveur Réessayez avec un back-off. Si cela persiste, écrivez-nous avec l'horodatage et le chemin appelé.
