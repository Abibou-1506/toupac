Authentification

Toute requête porte votre clé dans l'en-tête X-API-Key. Il n'y a ni jeton à rafraîchir, ni session à maintenir.

En-tête
X-API-Key: PREFIX.SECRET

Anatomie d'une clé

Une clé se lit en deux parties séparées par un point. Le préfixe (12 caractères) identifie la clé et peut apparaître dans vos journaux ; le secret ne doit jamais être journalisé — nous n'en conservons qu'une empreinte, personne chez TOUPAC ne peut vous le relire.

PartieExempleSensibilité
Préfixetpc_a1b2c3d4Identifiant, journalisable
Secret<votre_secret>Secret, jamais journalisé

Compte de service

Chaque clé API est rattachée à un compte de service technique de votre compagnie (API Bot). Les traces d'audit des opérations effectuées via l'API mentionnent ce compte comme initiateur — c'est le comportement normal, pas une erreur. Ce compte n'a ni mot de passe, ni accès au back-office : il n'existe que pour porter vos clés d'intégration.

Bonnes pratiques

  • Stockez la clé en variable d'environnement ou dans un gestionnaire de secrets — jamais dans le dépôt.
  • Une clé par environnement et par application : révoquer l'une n'interrompt pas les autres.
  • N'exposez jamais la clé dans un front web ou une application mobile : elle serait lisible par vos utilisateurs. Appelez l'API depuis votre serveur.
  • Rotation à la demande : nous émettons la nouvelle clé, vous basculez, nous révoquons l'ancienne. Aucune coupure.
  • En cas de fuite, écrivez-nous immédiatement — la révocation est instantanée.
